## Complaint-to-evidence ledger

1. **“A topology builder similar to GNS3.”** Topology Studio provides a node/network canvas,
   palette, links, automatic profile addressing, grid/layout persistence, selection/edit commands,
   validation and deploy flow. Evidence and operating instructions: [TOPOLOGY-STUDIO.md](../TOPOLOGY-STUDIO.md);
   GUI model coverage is in `tests/gui/test_topology_studio.py`.
2. **“Connect to machines via SSH/VNC and issue basic commands.”** V.3 provides real in-namespace
   SSH service, bounded exec and interactive sessions; V.4 provides the authenticated RFB relay
   and Raw/Hextile client path. Evidence: [v4-vnc-headless-gate.txt](../evidence/phase-v/v4-vnc-headless-gate.txt),
   the privileged SSH gate and [CONSOLE.md](../CONSOLE.md). Human framebuffer acceptance is
   explicitly deferred on this headless host.
3. **“Machines should be in 192.168.230-240.x.”** The default lab profile restricts networks to
   the eleven requested `/24`s, and allocation helpers are used by the builder. The explicit
   `rfc1918` compatibility escape hatch and safety rationale are documented in
   [TOPOLOGY.md](../TOPOLOGY.md) and [SECURITY.md](../../SECURITY.md).
4. **“Create a topology and scenario yourself.”** Topology and scenario libraries are persistent,
   restart-safe CRUD stores; Scenario Studio supports localized step authoring, bounded ICMP/TCP/
   `ssh_exec`/wait actions, assertions and cleanup. Evidence: [v5-scenario-studio-gate.txt](../evidence/phase-v/v5-scenario-studio-gate.txt)
   and [SCENARIOS.md](../SCENARIOS.md).
5. **“View more detailed logs.”** V.6 adds structured lifecycle/action records, bounded service and
   console files, UUID/deployment/session/experiment correlation, query/SSE/file APIs, diagnostics
   and the localized Logs page. Evidence: [v6-logs-gate.txt](../evidence/phase-v/v6-logs-gate.txt)
   and [LOGS.md](../LOGS.md).
6. **“Rename machines with normal names as well as IDs.”** Node `name` is a validated human label
   preserved independently from machine-readable `id` and shown in the canvas, tables, console,
   reports and logs. Covered by V.1/V.2 identity tests and [TOPOLOGY.md](../TOPOLOGY.md).
7. **“Machines should have UUIDs.”** Nodes carry stable RFC 4122 v4 UUIDs, which are exported,
   copyable, shown in inspection/console views, and included in reports/log correlations. The V.6
   real gate retrieves one node's full lifecycle by UUID.

## Resource cost

The structured log ring is capped at 5,000 records. `polmon.jsonl` rotates at 256 KiB with five
files maximum, service output is capped at 128 KiB per node/service file, console transcripts use
their existing bounded session policy, and API/UI responses are explicitly limited. The final
rootless gate used 146.65 seconds on this 4-core Linux host; the full privileged suite used
46.51 seconds. The local Linux bundle build consumed 128.9 MB client and 32.7 MB backend on disk.

## Known limitations and reason codes

- `v4.no_visual_validation_on_headless_server`: this server has no interactive display. RFB
  handshake, framebuffer bytes, pointer relay and client unit paths were tested headlessly; a
  human should accept the rendered VNC desktop on the operator's Windows machine.
- `v7.ci.billing_blocked`: the recorded GitHub Actions run `36314086429` failed every job to start
  with “recent account payments have failed or your spending limit needs to be increased”. Local
  gates are the source of truth for this phase; workflow YAML remains present and valid.
- `v7.windows_build_unavailable_on_headless_linux_host`: Windows EXE/portable artifacts were not
  fabricated. The Windows PyInstaller specs and release workflow remain version-driven and will
  build on a Windows runner when the billing blocker is removed.
- `v7.main_publication`: the release was merged with `--no-ff` and published on `origin/main`; the
  annotated `v0.5.0` tag points to merge commit `d75e353`.
