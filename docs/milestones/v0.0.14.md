# Milestone v0.0.14

VERSION: v0.0.14
STATUS: PASS

IMPLEMENTED: `polmon-benchmark` (`l0`, `l1`, `target`, `summarize`) with a reproducible method:
every run is admitted by the resource policy before creation, runs in a fresh worker interpreter
under per-run time and incremental-memory ceilings, and writes raw JSON plus flat CSV containing
host description, workload, limits, source commit, limitations, and every row. L0 sizes 10/25/50
run by default; 100/250 require `--large`. L1 namespace and the Phase I target (50 L0 + 2 L1
service endpoints over the hybrid TAP) run only in the privileged lab and otherwise record
`NOT RUN — environment unavailable`. Measures incremental and peak RSS (VmHWM reset first), exact
Python-heap bytes via `tracemalloc`, CPU utilisation, creation/teardown time, idle overhead,
controlled-traffic CPU per echo, packet loss, latency (cold/warm, p50/p95), L1 service process-tree
RSS, host MemAvailable delta, and verified cleanup. `tests/performance/` added (gate debt d).
`scripts/` created with five working helpers (gate debt c): `check.sh`, `privileged-tests.sh`,
`lab-cleanup.sh`, `run-benchmarks.sh`, `verify-release.sh`. `docs/BENCHMARKS.md` documents limits,
method, and fidelity classes.
DEFECT FOUND BY THE BENCHMARK AND FIXED: the first `--large` L0 run showed 20.7% loss at 100 and
74.3% at 250 endpoints. Synthetic protocol frames were delivered into bounded 256-frame receive
queues that nothing drained, so an endpoint stopped answering after 256 received frames (latent
since v0.0.6; it would also cap long scenario runs). The synchronous stack now consumes each
delivered frame; a regression test sends 747 frames to one endpoint (fails before, passes after).
The inherited untracked `benchmarks/synthetic.py` draft referenced non-existent `EngineStats`
fields and could not have completed a run; it was rewritten.
