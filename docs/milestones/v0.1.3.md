# Milestone v0.1.3 — Windows client fixes

VERSION: v0.1.3
STATUS: PASS

IMPLEMENTED: Waves 17–18 on top of v0.1.2. Real GUI tests now drive the Tk client against a live,
token-protected backend (offline error, token gating, validate → deploy → experiment → reset,
token never shown), under Xvfb in Linux CI and natively on the Windows runner. They found two
client defects, both fixed: (1) validate, deploy, and run-experiment workers read Tk variables
from the background thread ("main thread is not in main loop"); the API client is now built on
the UI thread; (2) on Windows a wrong or missing token surfaced as a raw `WinError 10053` because
the backend answered 401 before reading the request body; the backend now discards the bounded
body first and the client wraps connection-level `OSError`s in `ApiClientError`. The API token
field moved next to the backend URL. CI gained a `pip-audit` dependency-audit job.
TESTS EXECUTED: `scripts/check.sh`; `xvfb-run -a .venv/bin/python -m pytest -m gui`;

privileged"`; `.venv/bin/polmon-demo --output-dir docs/demo`; hosted Windows build (which runs the
GUI tests natively); CI (tests, GUI under Xvfb, benchmark smoke, dependency audit).
