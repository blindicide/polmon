# Milestone v0.3.0 — Self-contained backend artifacts (Windows + Linux)

VERSION: v0.3.0
STATUS: PASS

IMPLEMENTED: Phase III (`MANDATE-SELFCONTAINED.md`, plan `docs/SELF-CONTAINED-PLAN.md`).
(1) Qt-free PyInstaller backend executables: `polmon-backend.exe` (Windows, console, one-file)
and `polmon-backend-<version>-linux-x64.tar.gz` (one-folder, no Python/pip/venv), both with
`--version`, `--host`, `--port`, `--token-file` and a `--self-test` that loads uvicorn and the
application graph and completes a rootless L0 deploy → scenario → telemetry → report → reset.
(2) The client's **Local backend (L0 only)** preset starts the bundled backend on a free
loopback port with an ephemeral token, in its own process group (Windows: kill-on-close Job
Object), captures its log, detects its death, and stops it on disconnect and exit. The one-file
client embeds the backend; the portable zip ships `polmon-client.exe` and `polmon-backend.exe`
side by side. (3) Explicit fidelity: Windows/local backends are `l0_only`; L1/L2 deployment is
refused with HTTP 422 by the backend and before any request by the UI, with the Linux-host
requirement. (4) A second systemd unit for the extracted Linux bundle. (5) Defects found and
fixed while proving it: SQLite handle held open (Windows `WinError 32` in the packaged
self-test); one-file launcher kill orphaning the backend's Python child; overlapping sidebar rows
on a normal launch; build artifacts that kept a `dist/` prefix and broke the verify jobs.

TESTS EXECUTED: local rootless gate and `pytest -m gui` (Xvfb); local build of the Linux backend
bundle and `env -i` runs with and without sudo, the positive one guarded by
`scripts/privileged-tests.sh`; hosted CI (ubuntu + windows matrix), Build Windows and Build Linux
on 07f07d7, each with a fresh-runner job that downloads and re-verifies the uploaded artifacts;
the downloaded Linux artifacts re-checked on the development host.

KNOWN LIMITATIONS: The Windows local backend is L0-only by design (no network namespaces).
Executables are unsigned, so SmartScreen warns on first run. The Windows backend reports no
host memory/swap figures yet, so the admission memory reserve is not enforced there. L2 remains
unimplemented. Each one-file start unpacks to a temporary directory (the portable form avoids
it).
