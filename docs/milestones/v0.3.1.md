# Milestone v0.3.1 — Local backend lifecycle hardening (waves 1–5 after v0.3.0)

VERSION: v0.3.1
STATUS: PASS

IMPLEMENTED: (1) Windows backends report available physical memory (`GlobalMemoryStatusEx`) and
lifetime CPU (`GetProcessTimes`), so the admission memory reserve is enforced on the Windows local
backend too; swap is labelled "not reported by this host" instead of a bare dash. (2) The Local
backend keeps one persistent data directory (`<state>/polmon/data`): local experiment history,
reports and captures survive reconnects; per-start session directories hold only the log and are
pruned to the newest 20 (only log-only directories of finished clients; v0.3.0 sessions holding
data are never touched). Packaged self-tests run in temporary state. (3) Build Linux's
fresh-runner job starts `polmon-backend-bundled.service` through a real systemd user manager and
drives the HTTP workflow through it. (4) README "Which download?" table. (5) Stdin lifeline: a
client-owned backend shuts down gracefully at EOF on its stdin pipe — when the client stops it or
when the OS closes the pipe because the client died — fixing a reproduced Linux orphan (backend
reparented to PID 1 after the client was killed) and making Windows stops graceful (exit 0).

TESTS EXECUTED: local rootless gate and `pytest -m gui` (Xvfb); the Linux crash reproduction
before and after the fix (`polmon-client --local-backend-crash-test`); hosted CI, Build Windows
and Build Linux on each wave, the last set on e4186d3 (392571e adds only CHANGELOG text).
