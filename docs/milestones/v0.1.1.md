# Milestone v0.1.1 — security and hardening release

VERSION: v0.1.1

IMPLEMENTED: Post-MVP hardening waves 1–6 on top of v0.1.0, no architectural change.
Security: (1) the built-in L1 `static_http` service was `python -m http.server` in the backend's
working directory and listed it to every lab peer (verified: `.git/`, `.venv/`, reports, operator
files) — replaced by a standalone stdlib responder with a fixed body, no filesystem access,
bounded reads, a 32-connection cap, and an isolated interpreter; (2) the remotely controlled API
had no authentication — optional bearer-token auth added, checked before the body is read, and
the backend refuses a non-loopback bind without a token; (3) request bodies above 5 MiB
(including chunked) are refused with 413 before parsing. Robustness: command timeouts no longer
abort best-effort teardown; rollback deletes host veths that never reached their namespace;
deployment refuses to adopt pre-existing objects with generated names (verified with a real
pre-created namespace); client errors carry status/code/details. Performance: L1 deployment runs
one privileged `ip -batch` per namespace plus one on the host. Tooling: CI smoke-tests every
entry point, checks script syntax, and runs the small benchmark; the privileged host-network
guard compares nft structure (`nft -s -t`) because fail2ban updated its ban set mid-run once.
