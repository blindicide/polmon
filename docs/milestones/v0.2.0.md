# Milestone v0.2.0 — Qt desktop client and a fully exercised pipeline (Phase II)

VERSION: v0.2.0
STATUS: PASS

IMPLEMENTED: The operator's Phase II mandate. Plan first (`docs/UI-PLAN.md`, commit 6ce39a1,
before any implementation). (1) A PySide6 (Qt 6.11.2, LGPLv3; `PySide6-Essentials` as the new
optional `gui` extra) desktop client replacing the Tkinter client, one code base for Windows and
Linux: dashboard with live counters and limits; topology library/editor with backend validation
mapped to YAML lines, node/interface/MAC/IPv4 inspector and admission fit; deployment
(deploy with cancel-and-roll-back, destroy, reset, owned resources, live counters with
sparklines); scenario inspection and experiments with per-action live status, percent/step/
elapsed/ETA progress and graceful backend-side cancel; a live, filterable telemetry stream with
capture summary; reports (status, expected vs actual, observations, errors, resources, Markdown,
JSON, save); bounded benchmark jobs with explicit limits and retained results. All I/O runs off
the GUI thread (bounded `QThreadPool`, queued signals), every long operation is cancellable,
unreachable/slow/malformed/unauthorised/rejecting/dying backends give actionable messages,
light/dark themes, HiDPI, keyboard shortcuts, persisted settings, version in the title and About.
`--self-test` forces the offscreen platform and verifies Qt imports, the bundled platform plugins
(offscreen and native), QApplication, building/rendering/destroying the main window and the API
client configuration; `--version` keeps `polmon <version>`; `--smoke-start` shows the real window
on the native platform. (2) Additive backend API for the client: structured topology inspection
and listing, scenario validation against the loaded topology, `wait: false` experiments with live
progress (observations recorded as they happen), telemetry paging, experiment listing across
restarts, the Markdown report, and bounded benchmark jobs. Two backend defects found and fixed on
the way (a cancel arriving before the experiment thread started was lost; reused experiment IDs
failed inside SQLite). (3) Packaging: Windows one-file EXE with a pruned, verified Qt plugin set;
Linux one-folder bundle as a reproducible `.tar.gz` built on ubuntu-22.04, plus the wheel and the
systemd unit; AppImage built, measured and not shipped (BUILD-LINUX.md). (4) Workflows (actions
on Node 24 releases pinned by SHA, least privilege, concurrency, caching, timeouts): CI matrix
Linux + Windows with GUI tests under Xvfb/offscreen, entry-point and Qt smoke, coverage and
summary, real screenshots and a live E2E artifact, dependency audit; `build-windows.yml` and the
new `build-linux.yml`, each re-verifying its downloaded artifact on a fresh runner; `release.yml`
building both platforms, attaching both plus `SHA256SUMS.txt`, then downloading the published
assets and smoke-testing them on both OSes; manual `benchmark.yml`. Tkinter is removed: no
imports, tests or hidden imports remain, enforced by a hygiene test.

KNOWN LIMITATIONS: The Windows one-file EXE unpacks itself on every start (2–3.5 s); a one-folder
portable build would start in well under a second. The Linux bundle needs a glibc ≥ 2.35 host
and `libxcb-cursor0` for X11. Deployment calls are not interruptible on the backend, so Cancel on
a deploy rolls it back when the call returns. The GUI suite on Windows uses the offscreen platform
(native platform is covered by `--smoke-start` in CI and in both build workflows); visual layout
is checked by the committed screenshots, not asserted by tests. L2 remains unimplemented (as
v0.1.x).
